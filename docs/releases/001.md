## Development Progress

- Phase A backend foundation 已完成本地实现：Go HTTP server、静态资源内嵌、配置加载、Linux `/proc` 指标采集、64-byte 固定记录、UTC 日分段存储和区间聚合 API。
- 当前提供 `GET /api/v1/health`、`GET /api/v1/overview`、`GET /api/v1/metrics`、`GET /api/v1/applications` 和 `GET /api/v1/applications/{id}/releases`。
- Phase B read-only inventory 已完成本地实现：配置驱动的应用清单、固定参数 `systemctl show` 查询、仅 loopback 的 HTTP 健康检查、JSONL 发布记录读取，以及 `GET /api/v1/applications` 和 `GET /api/v1/applications/{id}/releases`。
- 应用状态错误以 `unknown`、`unavailable` 或 `unhealthy` 返回，不伪造成功；健康检查不跟随重定向。
- 服务配置强制使用 loopback 监听；Windows 本地运行不会伪造 Linux 指标，而是保留最后成功快照并报告采集错误。
- 本地认证不引入数据库：凭据文件仅保存 PBKDF2-SHA256 盐值和哈希，账号由 `origin-ops user` CLI 管理，会话仅保存在内存中。
- `/api/v1/health` 保持公开，其他 API 要求有效会话；登录、会话查询和注销使用 `/api/v1/session`。
- 改密、启用或禁用账号会立即使旧会话失效；会话 cookie 使用 `HttpOnly` 和 `SameSite=Strict`。
- `origin-ops release append` 仅允许向配置中已登记应用的 JSONL 文件追加规范化记录，不接受任意目标路径。
- 前端已增加登录页、账户菜单、退出登录、应用功能介绍和 systemd `Description`；没有公网 URL 的应用不会生成空链接。
